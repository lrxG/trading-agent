# 数据源（唯一：腾讯自选股 westock CLI）

> 本文是当前**唯一有效**的数据源说明。历史选型调研已归档至 `docs/archive/*.retired`（不参与生产、不作参考依据）。

## 一、唯一数据源

**腾讯自选股 CLI（`westock`）**，官方接口，本机已安装并实证可用（2026-10-19 通道验证 → 2026-10-21 全功能实测）。

**不引入任何第三方数据 SDK**。理由：
1. 腾讯 CLI 已覆盖系统全部契约键（行情/K线/板块/资金/龙虎榜/股东/财报/估值/预测/涨停池）；
2. 第三方库要多一个 venv、一个版本锁、一个断供风险，换不来额外字段；
3. 生产代码区零第三方依赖是**机械纪律**（`ingest.py` D1 判据按模式检查，不列举库名）。

## 二、系统用到的命令（全部实测）

### 行情与结构
| 契约键 | 命令 | 说明 |
|---|---|---|
| `daily_quote` | `kline <代码> --start D --end D` / `quote <代码> --date D` | 单日单批不触发行上限（53 批/日 ≈3 分钟） |
| `limit_up`（基础） | 由 `daily_quote` 自算（close==涨停价） | 涨停价按板块规则算；`boards` 递推 |
| `env_metrics` | 同上自算 + `changedist`（当日交叉核对） | 封板数/连板高度/炸板率/成交额/MA20 |

### 涨停池细节（`backfill_zt_reason`）
| 列 | 命令 | 口径 |
|---|---|---|
| 连板天数 | `screen ranking --type limitup_days --date D` | 校验用，不写回（boards 归自算） |
| 收盘封单量 | `screen ranking --type limitup_seal_volume --date D` | 单位**手** ⇒ ×100×当日 close 换**元** |
| 所属行业 | `sector constituent <板块码,...> --date D` | 申万二级行业名反查（批量 30/次） |
| 首次封板时间 | **无历史源** ⇒ 留空 | `minute` 只支持当日；该列只进证据文本，不参与机械判据 |

### 板块（`sector_seed`）
| 用途 | 命令 |
|---|---|
| 板块截面（涨幅/主力净流入/涨跌家数/龙头） | `sector ranking --date D` |
| 板块估值（PE/PB + 历史分位） | `sector valuation <板块码,...> --date D` |
| 板块盈利预测（增速/PEG） | `sector forecast <板块码,...> --date D` |
| 板块成份（行业反查用） | `sector constituent <板块码,...> --date D` |

### 其他可用能力（已实证，按需接入）
- `lhb` 全市场龙虎榜
- `chip` 筹码成本分析
- `technical` 技术指标
- `screen condition --expression` / `--preset` 条件选股（支持 `--date` 历史日）
- `screen ranking --type` 30+ 指标（两融/资金流/北向/评分/财务）
- `market-overview` 市场统计画像
- `trade-calendar` 交易日历
- `industry-chain` 产业链图谱

## 三、如实声明的数据缺口

| 契约键 | 状态 | 原因 |
|---|---|---|
| `dragon_tiger` | **声明空** | `fund lhb` 个股权总额 ≠ 契约席位粒度；营业部明细可空 ⇒ 不拼假席位 |
| `news` | **声明空** | `notice` 按票批量，无全市场入口 ⇒ 无全市场公告流 |
| `first_seal_time` | **留空** | 无历史分时接口（`minute` 仅当日） |

**禁止**：为填满契约而合成、拼接、外推任何缺失值。缺就是缺，如实标 `None` + 声明件登记。

## 四、通道健康检查

```bash
westock kline sh600241 --period day --limit 1        # 行情通道
westock changedist                                    # 涨跌分布通道
westock screen ranking --type limitup_days --limit 5  # 涨停池通道
westock sector constituent pt01801085 --limit 3       # 板块成份通道
```

任一不通 ⇒ 对应步骤停在该步并如实报错，不降级到其他数据源。

## 六、腾讯自选股 MCP 通道（2026-10-28 授权 · 会话内专用）

**两条通道分工，不可混用：**

| 通道 | 谁调得动 | 干什么 |
|---|---|---|
| `westock` CLI（`~/.local/bin/westock`） | Python 脚本 / cron / 批量循环 | **一切 pipeline 数据**（日链/盘中扫描/回填/回测数据重算）——脚本调不到 MCP，这是硬约束 |
| 腾讯自选股 MCP（连接器） | 仅模型在**会话内**调用 | CLI 给不了的四组：股价提醒 / 官方模拟盘 / 选股引擎 / 自选管理 |

**MCP 独有能力（CLI 无对应命令）**：
- `portfolio_tips_set` 股价提醒 → 系统缺的告警通道（P2 待办项）
- `portfolio_paper_*` 官方模拟盘（下单/持仓/盈亏/历史）→ replay 成交口径的**外部真值对照**
- `tool_filter` / `tool_strategy` / `tool_ranking` / `tool_label` / `tool_event` 选股引擎 → 与 C2 五路互为第三方交叉验证
- `portfolio_watchlist_*` 自选管理 → 人机交互用，系统不依赖

**注意**：MCP 走同一后端，限频与 CLI 相同（CLI 实测曾因限频失败 67%，靠分批 1800 码 + 重试 + 失败留痕修到 0.75%）。**不要以为 MCP 不受限**。
MCP 工具在会话启动时挂载——新授权的连接器需**新开会话**才出现在工具表。
