# 盘后复盘模板 v1（2026-10-30 定稿）

> 三套输出模板的第三套（盘前预案 v2 / 盘中扫描①~⑧ / 本模板）。
> 结构移植旧系统盘后复盘的判断层五件，机械数据由账本直读，判断层由 Agent 补写。
> 铁律：比分不修饰（错了就是 ❌）；漏选回放必须含"当时为什么不买"的机械原因，不许事后找补。

## L0 一句话 + 判断比分卡

- 一句话：今日市场定调 + 系统动作 + 结果（盈亏/躲过）
- 比分表：昨日预案④′消息面事件、⑥节 H 假设、盘中触发线——逐条 ✅❌🔶 打分
  - ✅ = 判断对且可执行；❌ = 判断错（必须写错因归类：数据/因果/时点/定价/执行）；🔶 = 不足以下结论（写缺什么证据）

## ① 市场账（机械 · 账本直读）

指数涨跌 / 广度（涨跌家数比）/ 涨停-炸板 / 成交额环比 / 主力净额 — 五行表，来源 settle.py

## ② H 假设终判（机械 + 判断）

- 每条 H：CREATED→（盘中失效？）→ 结算 verdict + 证据 + actual
- REFUTED 的必须写：错在哪个环节（输入数据错 / 推理链断 / 验证口径错）
- 表格：H id | 内容摘要 | verdict | 证据 | 错因归类

## ③ 决策对账（判断层）

- 盘前预案⑤节情景 vs 实际走出的情景：命中/偏离
- 盘前"不做清单"是否守住（做了不该做的=违规，哪怕赚钱也记违规）
- 持仓动作对账：该动的动了没、不该动的动了没

## ④ 漏选回放（判断层 · 防错过无记录）

- 今日涨幅前列（≥5% 或涨停）逐票过筛：当时可见吗（池内/池外）→ 事前有信号吗 → 为什么没进候选
- 产出：可捕获的漏选（进 Case 池）vs 不可捕获（妖股型，归档不加戏）

## ⑤ 教训固化（判断层 → 学习链入口）

- 本日 1~3 条教训，每条：现象 → 根因（五层穿透最深到哪层）→ 防重犯动作（改判据/改模板/改闸）
- 写明流转去向：进 demand_queue / 改 params / 仅记录

## 数据缺口声明

当日缺失的数据腿如实列（UNAVAILABLE 清单），零伪造。
